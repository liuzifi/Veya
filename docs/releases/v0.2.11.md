# Veya v0.2.11

本版本修复了 v0.2.10 发布后发现的两个问题：快捷面板的来源应用开关与窗口白条问题，以及设置页导航跳转位置不准的问题。

## 快捷面板：来源应用开关与窗口恢复修复

- 设置页"快捷面板"新增"显示来源应用"开关（默认开）：关闭后每条记录下方只显示复制时间，不再显示它来自哪个应用。
- 修复偶发的"打开设置/管理窗口后只剩白色方条、设置页打不开"：关闭快捷面板的原生窗口步骤（隐藏、恢复管理窗口尺寸）会被随后的"打开设置/管理"中止，而此时面板状态已清空，窗口就停在面板或折叠条的尺寸。现在会记住这笔尚未完成的尺寸恢复，由下一次打开管理/设置窗口补做；弹出面板时也不会再把过期的窗口尺寸当作管理窗口尺寸保存。
- CPU 渲染器：半透明阴影计入损坏区域和裁剪范围（修正此前遗留的编译错误，阴影的偏移与模糊半径不随图层变换缩放）。
- 条目快捷键：可在"条目属性"里录制快捷键（Esc 取消，保留"全局生效"标记，并与窗口唤起键冲突检查）。目前只保存快捷键，尚未接入系统级全局热键，按下不会触发粘贴。
- 全局快捷键支持 Win 键组合；仍要求至少含 Ctrl、Alt 或 Win 之一，单独的 Shift+字母不再被接受（否则会吞掉到处输入的大写字母）。

## 设置页导航：按真实位置跳转

- 设置页顶部的快捷导航（隐私/外观/窗口/快捷面板/数据/关于）改为按各分区标题的真实位置跳转。此前用写死的滚动百分比，在 900×700 的窗口里"数据"会停在标题上方约 360px（落在快捷面板分组中间），"快捷面板""窗口"也偏 70~80px，新增设置行后还会继续漂移。
- 实现 `SectionOffset` widget operation，遍历控件树找到分区标题容器的真实 Y 坐标，再用 `scrollable::scroll_to` 精确定位。

## 升级与验证

- 下载下方 `veya-setup-0.2.11.exe` 安装即可，可直接覆盖旧版本，无需卸载。
- 这是 Windows 7 SP1 兼容构建（静态 CRT，x86_64-win7-windows-msvc）。
- 验证步骤：
  1. 打开设置 → 快捷面板，确认"显示来源应用"开关存在且默认开启；关闭后唤起面板确认每条记录不再显示来源应用。
  2. 反复"唤起面板 → 打开设置 → 关闭设置 → 唤起面板"，确认不会出现白色方条或设置页无法打开的情况。
  3. 打开设置，依次点击导航栏的"隐私/外观/窗口/快捷面板/数据/关于"，确认每次滚动都精确停在对应分区标题。
  4. 在条目属性中录制快捷键（含 Ctrl/Alt/Win 修饰键），确认 Esc 可取消录制；勾选"全局生效"后重新录制确认标记保留。

# Veya v0.2.9

本版本是 v0.2.8 的构建修复版：功能与 v0.2.8 完全一致，仅修复了 v0.2.8 在 Windows CI 上暴露的编译错误与测试预期偏差，使发布构建可以顺利通过。如果你已安装 v0.2.8，可直接覆盖安装 v0.2.9，无需卸载。

## v0.2.8 构建修复

- **`BIF_USENEWUI` 导入缺失**：`veya-windows/src/platform/dialog.rs` 原先从 `windows::Win32::UI::Shell` 导入 `BIF_USENEWUI`，但该常量在 windows-rs 0.61.3 中不存在于 `Shell` 或 `Shell::Common` 模块。改为在文件内定义本地常量 `const BIF_USENEWUI: u32 = 0x00000040;`（取自 Windows SDK `shlobj_core.h`），行为与系统常量完全一致。
- **`WorkerHandle::send` 方法不存在**：`veya-desktop/src/app/data.rs` 两处调用 `self.worker.send(WorkerCmd::SetDbPath { .. })`，但 `WorkerHandle` 结构体只有 `cmd_tx` 字段，需改为 `self.worker.cmd_tx.send(...)`。
- **`DataJob::locked` 私有方法跨模块调用**：`veya-desktop/src/app/settings.rs` 调用 `self.data_job.locked()`，但 `locked` 在 `data.rs` 中是私有 `fn`。改为 `pub(super) fn`，供同 `app` 模块下的 `settings.rs` 使用。
- **借用冲突**：`veya-desktop/src/app/quick.rs` 的 `build_quick_folded` 在 `let Some(quick) = &mut self.quick` 可变借用期间，又在赋值右值调用 `self.quick_window_height()` 触发不可变借用，造成 E0502。改为在进入可变借用前预计算 `nominal_size`，复用于折叠与展开两个分支。
- **测试夹具缺少新增字段**：`isolated_app()` 测试构造 `App` 时缺少 v0.2.8 新增的 `quick_font_size_input` 和 `quick_settings_owned` 字段（E0063）。补齐为 `String::new()` 与 `false`。
- **`rapid_toggle_aborts_old_window_tasks_before_the_next_session` 测试预期错误**：该测试在 `dismiss_quick` 后断言 `window_tasks.len() == 2`，但 `dismiss_quick` 开头会调用 `advance_window_generation`，它会先中止并清空旧任务再注册自己的关闭任务，所以只剩 1 个 handle。原期望 2 等于要求"打开时的任务在关闭后还活着"，正好违背该机制的目的。改为期望 1 并补充说明。
- **`restoring_management_state_snapshots_the_saved_panel_size_immediately` 测试顺序错误**：该测试在 `show_quick` 之前就把 `window_size` 改成窄面板尺寸，导致保存的"管理窗口尺寸"自然是窄的。改为先 `show_quick`（此时快照到原始管理尺寸），再模拟原生窗口缩小为窄面板，断言才能验证"快照的是管理尺寸而非窄面板尺寸"。
- **`cargo fmt` 全工作区统一**：修复了 18 处 rustfmt 偏差（跨 6 个文件），并修正了 `app.rs` 中 `Self` 构造体字段的缩进（16 空格 → 12 空格）以及 `dialog.rs` use 语句的字母序排列。

## 快捷面板右键菜单

- 在快捷粘贴面板内右键点击任意条目时弹出上下文菜单，菜单项包括：删除、编辑、新建、属性、排序。
- **删除**：立即从列表和存储中移除该条目。
- **编辑**：仅文本条目可用，弹出编辑框预填当前内容，Enter 保存、Esc 取消；超过 512 字符的文本不可编辑（会截断），提示在管理窗口中处理。
- **新建**：弹出编辑框输入文本，保存后作为新记录插入数据库，序号从 `0x80000000` 起独立编号，不会被之后复制产生的相同剪贴板序号覆盖。
- **属性**：弹出属性面板，可设置条目级全局快捷键、自动删除开关、固定位置（不固定 / 固定到顶部 / 固定到底部）。
- **排序**：快速移动到顶部、移到底部、固定到顶部、固定到底部，菜单项根据当前 `pin_rank` 动态显示。
- 菜单项之间用分隔线区分功能组；非文本条目的编辑项显示为禁用并标注"仅文本"或"内容过长"。

## 核对修复

- 滚轮：按系统"每次滚动行数"缩放时以 Windows 默认的 3 行为基准（iced 每个滚轮单位滚动 60px，本来就对应 3 行），默认设置下速度与之前相同，1 行变慢、10 行变快；此前直接乘以行数会让默认设置快 3 倍。
- 滚轮（整屏滚动）：当系统"鼠标属性 → 每次滚动行数"设为"一次滚动一个屏幕"时，原先每滚动一格会跳约 600px（接近快捷面板的整屏高度，列表被甩过头），现改为退回默认 3 行的行增量，一格只前进两三行。
- 快捷面板：底部入口由"管理历史"改为"设置"，打开设置页更直接；"管理历史"仍可从设置或主菜单进入。
- 亮色模式：右键上下文菜单的投影过深（alpha 0.20），在白底上像一道黑边，已降至 0.08。
- 历史排序与分页：置底记录现在排在列表最后（此前排在置顶记录之后、普通记录之前）；翻页改为按"置顶组 + 时间"定位，固定位置的记录不再在每一页重复出现，也不会在页尾落在置顶组内时漏掉记录。
- 取消固定同时清除置顶/置底位置，不再留下"已取消固定却仍排在顶部或底部"的记录。
- 在 Veya 内新建的文本记录使用独立的序号区间（从 `0x80000000` 起），不会再被之后复制产生的相同剪贴板序号覆盖。
- "自动删除"开关现在生效：带该标记的记录粘贴后会被删除。移到顶部时会立即刷新列表。
- 快捷面板：折叠状态下悬停展开后，点击折叠按钮会保持展开，而不是立刻折回；快速移入移出不会把窗口记成过窄的展开尺寸；"始终置顶"设置不再让管理窗口也保持置顶；超过 512 字符的文本不再能在快捷面板里编辑（原来保存会截断后半部分）；条目属性里的"条目快捷键"只在已设置时才可点击清除；已粘贴标记改为左侧红条（原为整圈红边），浅色下交替行底色可见。
- 快捷面板（悬停展开内容不显示）：折叠后鼠标移入标题栏触发的自动展开，窗口标签已变为"展开"但内容区却仍是空白——根因是展开尺寸 `expanded_size` 在原生窗口尚未报告完整尺寸的边界场景下被过时的窄条尺寸覆盖，或首次打开即为零；现在折叠/展开时会以标称尺寸兜底，确保鼠标悬停展开后窗口内容也能正确显示。
- 设置页：快捷面板的行数、不透明度输入框会随已保存设置（启动、还原备份后）同步，不再显示默认值。
- 快捷面板（透明度设置不生效）：在设置页修改"面板不透明度"并点击"应用"后窗口透明度没有任何变化——根因是应用逻辑被 `self.quick.is_some()` 守卫，设置页打开时 `self.quick` 为 `None`，导致透明度只写入配置、不作用于当前可见的共享窗口；现在点击"应用"会立即把新透明度应用到设置窗口，给出实时预览。管理窗口（历史页）与从托盘恢复的窗口始终保持完全不透明，预览的半透明状态不会泄漏到管理窗口。
- 修复 Windows 编译错误：`window_place.rs` 中 `ClientToScreen` 的导入位置、`GetGUIThreadInfo` 与 `ClientToScreen` 的返回值判断、`SetLayeredWindowAttributes` 的颜色键参数。
- 全工作区 `cargo fmt` 格式统一。
- 移除 `strip_folded` 死方法和补充 `fit_and_anchor` 测试导入。

## 快捷面板字体设置

- 在设置页"快捷面板"分组新增"文字大小"输入框（11–18 px，默认 13）和"字体"切换（默认 / 等宽）。调整文字大小后，面板内序号、内容图标、正文/元数据字号、行间距、行内边距与序号列宽会按比例同步缩放，紧凑模式下可在小窗口显示更多条目。
- "等宽"字体（Consolas）仅含 ASCII 字形，适合英文/数字内容；含中文的条目仍建议使用"默认"（微软雅黑 UI）字体。

## 快捷面板悬停展开开关

- 在设置页"快捷面板"分组新增"悬停自动展开"开关（默认开启）。开启时，折叠后面板鼠标移入标题栏即自动展开内容；关闭后，折叠态不再随鼠标移入自动展开，需要手动点击展开按钮，避免误触。
- 修复了"悬停展开后窗口内容不显示"的 bug：展开尺寸在边界场景下会回退到标称尺寸，悬停展开后窗口内容区会正确恢复并显示。

## 设置页快捷分区导航

- 在设置页顶部增加一排固定显示的快捷导航条（隐私 / 外观 / 窗口 / 快捷面板 / 数据 / 关于），点击对应条目即可把设置列表滚动并精准定位到该分区，无需手动翻找。
- 导航条固定在列表上方，滚动设置内容时始终可见；使用相对偏移（`RelativeOffset`）按各分区自然高度校准，并向上微偏让分区标题落在导航条下方、保留少量上文；超出范围的偏移会由 iced 自动钳制，安全无害。

## 快捷面板设置开关竞态修复

- 设置页"快捷面板"分区下的开关（面板窗口置顶、失焦自动关闭、悬停自动展开、粘贴后移到顶部等）点击后状态会被回滚、看似不生效——根因是 worker 每次循环回传的 snapshot 仍携带旧 `quick_settings`，而 UI 端用 `self.state = next` 整体覆盖，把用户刚改的开关值又覆盖回去，形成竞态（与此前透明度设置不生效同类）。
- 修复：新增 `quick_settings_owned` 标志。首次 snapshot 到达后由 UI 接管 `quick_settings`，后续 snapshot 覆盖时保留 UI 端值；仅在启动与数据库还原后重置为 `false`，让 worker 重新加载的设置能流回 UI。开关点击后即时更新本地状态并发送 `SetQuickSettings`，不再被旧 snapshot 回滚。

## 窗口生命周期与任务栏角色

- **症状**：打开快捷粘贴面板时任务栏会冒出"设置面板"的窗口图标，面板关闭后图标与对应窗口仍在任务栏残留，给人"快捷面板顺带启动了设置窗口"的错觉。
- **根因**：Veya 是单窗口架构——快捷面板、管理窗口、设置页共用同一个 `iced` 原生窗口，只是通过 `iced::window::Mode`（`Windowed`/`Hidden`/`Minimized`）和 `view()` 分发切换。问题不在"多开了一个窗口"，而在共享窗口的**任务栏角色**与**显隐生命周期**：
  1. 启动时 `boot()` 无条件以 `Mode::Windowed` 显示主窗口，托盘可用时也会在任务栏留一个管理/设置图标；
  2. 窗口默认带 `WS_EX_APPWINDOW`（普通任务栏按钮），快捷面板打开后没有切换为 `WS_EX_TOOLWINDOW`（不在任务栏），于是面板期间任务栏仍显示管理/设置按钮；
  3. `WindowAction::Minimize` 把 `window_hidden` 置 `false`，最小化到任务栏时图标一直驻留，且热键状态判断会把"已最小化"误当成"可见"；
  4. 迟到的窗口任务（`QuickShown`/`WindowRestored`/`TargetRestored`）只靠 generation 完成时检查，旧流可能已经排队了 show/hide/resize/focus 效果，快速反复开关会撞车。
- **修复**：
  - 新增 `set_window_taskbar_visible(hwnd, visible)`：用 `SetWindowLongPtrW` 在 `WS_EX_APPWINDOW` ↔ `WS_EX_TOOLWINDOW` 之间切换（保留其余扩展样式），`SetWindowPos(SWP_FRAMECHANGED)` 刷新，再用 `ITaskbarList::AddTab/DeleteTab` 更新 Shell 任务栏缓存；调用前用 `GetWindowThreadProcessId == GetCurrentProcessId` 校验 HWND 归属，绝不触碰其他进程同名"Veya"窗口。
  - `prepare_initial_window` 取代 `show_initial_window`：托盘可用时以 `visible=false`（`Mode::Hidden`）启动，启动阶段任务栏不出现管理/设置图标，直到显式激活。
  - 每次窗口转换都设置任务栏角色：快捷面板/隐藏态→工具窗口（不在任务栏），管理/设置→普通窗口（在任务栏）。
  - 新增 `window_tasks: Vec<iced::task::Handle>` 与 `guard_window_task`：每个窗口任务用 `Task::abortable()` 包裹，handle 存入向量；`advance_window_generation` 在开启下一会话前先 `drain` 并 `abort` 所有旧 handle，从源头掐断迟到效果，而非仅靠完成时 generation 检查。
  - 新增 `WindowSignal::OpenSettings` 显式变体，托盘"设置"与热键"激活"不再被合并混淆；热键在面板已可见时直接 `Hide`（不再 `Minimize`），不留任务栏按钮。
  - `view()` 在 `window_hidden` 时返回空 `Space`，避免隐藏/关闭期间渲染设置或管理视图。
- **隔离 Windows 验收步骤**（需在带 Rust 1.99.0 的 Windows 机器上 `cargo test` 后手动验收）：
  1. 启动 Veya（托盘可用）：任务栏**不**出现 Veya 图标，仅托盘里有图标；
  2. 按热键打开快捷粘贴面板：面板出现，任务栏**仍不**出现 Veya 图标；
  3. 从托盘"设置"打开设置页：任务栏出现 Veya 图标，设置页正常显示；
  4. 关闭设置窗口（托盘模式）：任务栏图标消失，进程仍在托盘；
  5. 快速反复按热键开关快捷面板 10 次以上：任务栏始终不出现图标，面板每次都能正确开关，无卡顿/残留；
  6. 从托盘"打开窗口"恢复管理窗口：任务栏图标出现，管理历史正常；
  7. 最小化管理窗口：任务栏图标保持存在（与托盘隐藏不同），恢复后无异常。

## 数据库存储路径自定义

- 设置页"数据"分区新增"数据库存储路径"设置：提供文本输入框用于填写自定义数据库文件夹，旁边通过"浏览…"按钮调用原生文件夹选择对话框（带 COM 初始化，适配后台线程调用），选中后自动回填输入框。
- 路径留空时回退到默认位置；输入框下方常驻提示默认路径，标签旁展示当前生效路径，便于确认自定义是否已保存。
- 自定义路径持久化在 `%APPDATA%\Veya\veya.cfg` 伴生配置文件中（独立于数据库本身，避免"配置存在数据库里"的循环依赖），点击"应用"后写入，提示"重启 Veya 后生效"；本次运行中的数据库连接保持不变。
- 输入框填有非默认值时出现"恢复默认"小按钮，一键清空配置并回退默认路径；备份与还原功能使用的安全副本目录会跟随配置目录变化。
- 数据库忙碌（备份/还原进行中）时路径相关操作全部锁定，避免中途修改导致数据错位。

## 构建与升级

- 可覆盖安装 v0.2.7 或 v0.2.8，历史和设置默认保存在 `%APPDATA%\Veya\veya.db`，可通过设置页自定义存储位置；安装与卸载保留用户数据。
- 本版为 Win7 SP1 兼容构建（静态 CRT，x86_64-win7-windows-msvc）。
- 发布安装包文件名带版本号：`veya-setup-0.2.9.exe`。

## 已知限制

- 分组目前仅支持快捷粘贴面板中的过滤；管理历史面板的分组过滤将在后续版本中完善。
- 安装包未签名，Windows 可能提示未知发布者。
